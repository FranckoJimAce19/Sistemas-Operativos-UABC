\section{Introducción}
    Un proceso es un programa en ejecución y la unidad de trabajo de los sistemas de cómputo modernos. A diferencia de un programa estático almacenado en disco, un proceso es una entidad dinámica que posee su propio espacio de direcciones, contador de programa y recursos asignados por el sistema operativo. Desde el momento en que un proceso es creado hasta que finaliza su ejecución, atraviesa distintos estados que el núcleo del sistema operativo administra de forma continua. \par
    En esta práctica se analizará el ciclo de vida de un proceso con la finalidad de lograr un entendimiento a fondo de los mismos mediante la creación de un árbol de procesos y la creación de un proceso \textit{zombie}. El árbol de procesos permite observar cómo un proceso padre puede generar múltiples procesos hijos de manera jerárquica usando la llamada al sistema \texttt{fork()}, y cómo cada hijo puede a su vez ejecutar tareas específicas del sistema operativo. Por otro lado, el proceso zombie ilustra qué ocurre cuando un proceso hijo termina su ejecución pero el padre aún no ha recogido su código de salida, situación que deja al proceso en un estado residual dentro de la tabla de procesos del sistema.

\section{Justificación}
    El estudio del ciclo de vida de un proceso es indispensable para cualquier estudiante de sistemas operativos, ya que todo el software que se ejecuta en una computadora lo hace en el contexto de uno o más procesos. Los sistemas operativos modernos dependen de mecanismos precisos de creación, sincronización y terminación de procesos para garantizar la estabilidad y el uso eficiente de los recursos del sistema. Sin una comprensión sólida de estos mecanismos, resulta difícil diseñar software que se comporte correctamente en entornos multitarea o que interactúe de forma segura con el sistema operativo. \par
    Esta práctica se justifica en la necesidad de desarrollar competencias prácticas para crear y analizar jerarquías de procesos mediante la llamada al sistema \texttt{fork()}, sincronizar la ejecución del proceso padre con sus hijos a través de \texttt{wait()}, y ejecutar comandos del sistema operativo desde código en C usando \texttt{system()}. Asimismo, reproducir un proceso zombie permite comprender las consecuencias de no gestionar correctamente la terminación de los hijos, lo que en aplicaciones reales puede derivar en fugas de recursos y degradación del rendimiento del sistema. De esta manera, la práctica establece las bases necesarias para abordar temas más avanzados del curso, como la planificación de la CPU, la comunicación entre procesos y la administración de memoria.

            \item \textbf{Nodo C:} Mostrará el mensaje ``Soy Nodo C, mi PID es: \#\#\#\# y el PID de mi nodo padre es: \#\#\#\#''. Posterior a eso, mostrará el contenido del directorio actual.
            \item \textbf{Nodo D:} Mostrará el mensaje ``Soy Nodo D, mi PID es: \#\#\#\#'' y ejecutará el comando adecuado para mostrar la lista de los procesos actuales.
            \item \textbf{Nodo E:} Deberá mostrar el mensaje ``Soy Nodo E, mi PID es: \#\#\#\#'' y la fecha del sistema.
            \item \textbf{Nodo F:} Mostrará el mensaje ``Soy Nodo F, mi PID es: \#\#\#\#'' para posteriormente listar la lista de los procesos actuales.
            \item \textbf{Nodo G:} Mostrará el mensaje ``Soy Nodo G, mi PID es: \#\#\#\#'' y creará un archivo llamado \texttt{estructura\_procesos}.
        \end{itemize}

        \item ¿Cuál es la diferencia entre \texttt{exec()} y \texttt{system()}?

        \item Realizar un programa en C que cree un proceso hijo el cual pasará a convertirse en un proceso \textit{zombie}. Este deberá permanecer en el sistema por más de un minuto, o bien, hasta que el usuario termine el proceso padre con la ayuda del comando de shell \textit{kill} desde la terminal. Para poder visualizar al proceso zombie, el programa deberá ser ejecutado como proceso de fondo (\textit{background}) y desde esa misma terminal, utilizar el comando \texttt{ps -l} para visualizar los procesos actualmente en ejecución.
    \end{enumerate}

\section{Marco Teórico}
    \subsection{El Ciclo de Vida de un Proceso}
    Un proceso puede estar en alguno de los siguientes estados:
    \begin{itemize}
        \item \textbf{New} --- el proceso está siendo creado.
        \item \textbf{Running} --- las instrucciones están siendo ejecutadas.
        \item \textbf{Waiting} --- el proceso está esperando algún evento (I/O o recepción de una señal).
        \item \textbf{Ready} --- el proceso está en espera de ser asignado a un procesador.
        \item \textbf{Terminated} --- el proceso ha terminado su ejecución.
    \end{itemize}

    \subsection{Creación de Procesos}
    Durante la ejecución de un proceso, es posible que este cree múltiples procesos nuevos. El proceso que crea uno nuevo es llamado proceso padre, mientras que el nuevo es referido como hijo de dicho proceso. \par
    Para crear un proceso se utiliza la llamada al sistema \texttt{fork()}. La función \texttt{fork()} retorna un \texttt{0} para el proceso hijo, mientras que para el padre retorna el PID del proceso hijo. \par
    Ambos procesos continúan con las instrucciones siguientes al \texttt{fork()} ya que el proceso hijo es un duplicado del proceso padre, es decir, tiene el mismo programa y datos. Sin embargo, esto no descarta la posibilidad de que el hijo pueda cargar un nuevo programa. \par
    Cuando un proceso padre crea un nuevo proceso, existen dos posibilidades en términos de ejecución:
    \begin{itemize}
        \item El proceso padre continúa su ejecución de forma concurrente con el proceso hijo.
        \item El proceso padre espera a que el proceso hijo haya terminado (llamada al sistema \texttt{wait()}).
    \end{itemize}

    \subsection{Diferencia entre \texttt{exec()} y \texttt{system()}}
    Ambas funciones permiten ejecutar comandos o programas externos desde un proceso en C, pero difieren en su comportamiento:
    \begin{itemize}
        \item \textbf{\texttt{exec()}}: sustituye completamente la imagen del proceso actual (código, datos y pila) con la del nuevo programa. Si tiene éxito, el proceso original nunca retorna; solo el nuevo programa continúa ejecutándose bajo el mismo PID.
        \item \textbf{\texttt{system()}}: crea un proceso hijo con \texttt{fork()}, ejecuta el comando indicado en un shell (\texttt{/bin/sh -c}) dentro de ese hijo, y espera su terminación con \texttt{wait()}. El proceso padre \textit{sí} continúa su ejecución una vez que \texttt{system()} retorna.
    \end{itemize}

    \subsection{Ejecución en segundo plano (\textit{background})}
    En la shell de Linux, agregar el operador \texttt{\&} al final de un comando lo envía al fondo (\textit{background}), de modo que la terminal queda libre para ejecutar otros comandos mientras el proceso continúa corriendo.

    \subsubsection{nodoP.c — Nodo raíz}
    El Nodo P muestra el mensaje de presentación y el PID de su propio padre. Crea al Nodo A con \texttt{fork()} y espera a que termine con \texttt{waitpid()}. Una vez que todos los procesos del árbol han concluido, imprime el mensaje final.

    \begin{lstlisting}[caption={nodos/nodoP.c -- nodo raiz del arbol.}]
#include <stdio.h>
#include <stdlib.h>
#include <sys/wait.h>
#include <unistd.h>
#include "nodos.h"

void nodoP(void)
{
    int pidA;

    printf("Soy el padre de todos los siguientes procesos, "
           "los cuales realizan distintas tareas\n");
    printf("El PID de mi nodo padre es: %d\n", getppid());
    fflush(stdout);

    pidA = fork();

    if (pidA == 0) {
        nodoA();
        exit(0);
    }
    waitpid(pidA, NULL, 0);

    printf("Todos los procesos han terminado\n");
}
    \end{lstlisting}

    \subsubsection{nodoA.c — Crea B y C, ejecuta \texttt{clear}}
    El Nodo A muestra su PID, crea los Nodos B y C, espera a que ambos terminen y luego —previa confirmación del usuario— ejecuta el comando \texttt{clear}. La función auxiliar \texttt{esperarTecla()} desactiva temporalmente el modo canónico del terminal para capturar una sola tecla sin necesitar \textit{Enter}.

    \begin{lstlisting}[caption={nodos/nodoA.c -- crea a B y C y ejecuta clear.}]
#include <stdio.h>
#include <stdlib.h>
#include <sys/wait.h>
#include <termios.h>
#include <unistd.h>
#include "nodos.h"

static void esperarTecla(void)
{
    struct termios attrsViejos;
    struct termios attrsNuevos;
    int esTerminal;

    printf("\nPresiona cualquier tecla para limpiar la pantalla...");
    fflush(stdout);

    esTerminal = isatty(STDIN_FILENO);

    if (esTerminal && tcgetattr(STDIN_FILENO, &attrsViejos) == 0) {
        attrsNuevos = attrsViejos;
        attrsNuevos.c_lflag &= ~(ICANON | ECHO);
        tcsetattr(STDIN_FILENO, TCSANOW, &attrsNuevos);
        getchar();
        tcsetattr(STDIN_FILENO, TCSANOW, &attrsViejos);
    } else {
        getchar();
    }
    printf("\n");
}

void nodoA(void)
{
    int pidB;
    int pidC;

    printf("Soy Nodo A y mi PID es: %d\n", getpid());
    printf("El PID de mi nodo padre es: %d\n", getppid());
    fflush(stdout);

    pidB = fork();
    if (pidB == 0) { nodoB(); exit(0); }

    pidC = fork();
    if (pidC == 0) { nodoC(); exit(0); }

    waitpid(pidB, NULL, 0);
    waitpid(pidC, NULL, 0);

    esperarTecla();
    system("clear");
}
    \end{lstlisting}

    \subsection{Diferencia entre \texttt{exec()} y \texttt{system()}}
    Como respuesta al punto 2: \texttt{exec()} sustituye completamente el proceso actual con la del nuevo programa (el proceso original no continúa), mientras que \texttt{system()} crea un proceso hijo temporal con \texttt{fork()}, ejecuta el comando en un shell dentro de ese hijo y espera su terminación con \texttt{wait()}, permitiendo que el proceso padre continúe después. En esta práctica se usó \texttt{system()} en los nodos B, C, D, E, F y G precisamente para conservar el proceso de cada nodo mientras ejecuta comandos del sistema.

    \subsection{Proceso zombie}
    El programa \texttt{zombie.c} crea un proceso hijo que termina de inmediato con \texttt{exit(0)}, convirtiéndose en zombie porque el padre no llama a \texttt{waitpid()} de inmediato. El padre espera 65 segundos en un bucle \texttt{for}, lo que permite observar el proceso zombie con \texttt{ps -l} durante ese tiempo. Al finalizar, el padre llama a \texttt{waitpid()} para limpiar la entrada de la tabla de procesos.

    \begin{lstlisting}[caption={zombie.c -- crea un proceso zombie observable.}]
#include <stdio.h>
#include <stdlib.h>
#include <sys/wait.h>
#include <unistd.h>

int main(void)
{
    int pidHijo;
    int i;

    pidHijo = fork();

    if (pidHijo == 0) {
        printf("[HIJO]  PID: %d | Termino y me quedo como zombie\n",
               getpid());
        fflush(stdout);
        exit(0);
    }

    printf("[PADRE] PID: %d | Cree al hijo (zombie) PID: %d\n",
           getpid(), pidHijo);
    fflush(stdout);

    //Tiempo de espera para el padre
    for (i = 0; i < 65; i++) {
        sleep(1);
    }

    waitpid(pidHijo, NULL, 0);
    printf("Se murio el zombie \n");
    fflush(stdout);

    return 0;
}
    \end{lstlisting}

    Para ejecutarlo en segundo plano y observar el zombie desde la misma terminal se usa el operador \texttt{\&}:
    \begin{lstlisting}[language=bash, caption={Ejecución del zombie en background y verificación con ps.}]
$ ./zombie &
[1] 12345
[PADRE] PID: 12345 | Cree al hijo (zombie) PID: 12346
[HIJO]  PID: 12346 | Termino y me quedo como zombie
$ ps -l

\section{Conclusiones}
    El desarrollo de los programas del árbol de procesos y del proceso zombie permitió aplicar de manera directa los conceptos del ciclo de vida de un proceso en Linux, así como el uso de las llamadas al sistema \texttt{fork()}, \texttt{waitpid()} y \texttt{exit()}. \par
    La implementación del árbol de procesos demostró cómo un proceso puede crear múltiples hijos de forma jerárquica: cada nodo creó sus hijos con \texttt{fork()} y esperó su terminación con \texttt{waitpid()}, garantizando una sincronización correcta. La organización del código en módulos separados —un archivo por nodo— facilitó su comprensión y mantenimiento. \par
    La diferencia entre \texttt{exec()} y \texttt{system()} resultó clave: \texttt{system()} conserva el proceso padre mientras ejecuta un subproceso en un shell, lo que lo hace adecuado para los nodos de esta práctica; \texttt{exec()} en cambio reemplaza completamente el proceso actual, siendo más eficiente cuando no se necesita retornar al código original. \par
    El programa zombie ilustró un escenario real de gestión incorrecta de procesos: si el padre no recoge el código de salida del hijo, la entrada del hijo permanece en la tabla de procesos. Este comportamiento, verificado con \texttt{ps -l}, refuerza la importancia de llamar a \texttt{wait()} en todo programa que cree procesos hijos. En conjunto, la práctica fortaleció la comprensión del funcionamiento del software en un sistema de cómputo y estableció la base para abordar temas más avanzados del curso.
